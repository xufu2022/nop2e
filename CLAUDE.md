# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm test                  # run all tests (headless)
npm run test:headed       # run with browser visible
npm run test:ui           # open Playwright UI mode
npm run test:debug        # run with Playwright inspector
npm run test:chromium     # run chromium only
npm run test:report       # open last HTML report
npm run test:uat-ca       # run against UAT-CA environment (uses envs/uat-ca.env)

# Run a single test file
npx playwright test tests/path/to/spec.ts

# Run a single test by title
npx playwright test -g "test title here"

# Run setup only (re-authenticate)
npx playwright test --project="admin setup"
```

## Environment Configuration

Environment files live in `envs/`. The active file defaults to `.env` and can be switched with `ENV_FILE=uat-ca.env`.

`envs/.env` is gitignored — never commit it. Copy it from a colleague or password manager. Required variables:

```
BASE_URL=
ADMIN_USERNAME=
ADMIN_PASSWORD=
BUYER_USERNAME=
BUYER_PASSWORD=
```

## Authentication Architecture

Authentication uses **Playwright's storageState pattern** — login runs once per role at the start of a test run, not per test.

Flow:
1. `tests/auth/admin.setup.ts` logs in via UI and saves the session to `playwright/.auth/admin.json`
2. `playwright.config.ts` declares `admin setup` as a dependency of the `chromium` project and sets `storageState: 'playwright/.auth/admin.json'`
3. Every test page opens already authenticated — no login UI interaction during tests

The `.auth/` directory is gitignored. If authentication breaks mid-run, delete `playwright/.auth/*.json` and re-run to force fresh login.

`AdminBasePage.login()` and `PublicBasePage.login()` still exist for tests that explicitly need to test the login flow.

## Writing Tests

Always import `test` and `expect` from `tests/fixtures/index.ts`, not from `@playwright/test` directly:

```ts
import { test, expect } from '../fixtures';

test('admin can view dashboard', async ({ authenticatedAdmin }) => {
  await authenticatedAdmin.navigateToDashboard();
  await expect(authenticatedAdmin.page).toHaveURL(/\/Admin/);
});
```

Available fixtures: `adminPage`, `publicPage`, `header`, `footer`, `authenticatedAdmin`.

Use `routes` from `tests/fixtures/routes.ts` for all URL paths instead of hardcoding strings.

## Spec-Driven Test Generation (`/generate-tests`)

The skill at `.claude/commands/generate-tests.md` automates the full cycle:
**specs → clarification → MCP page exploration → POMs → spec files**

Invoke with `/generate-tests` and either pass a specific file path or no argument (scans all of `docs/specs/*.md` automatically).

Spec files live in `docs/specs/` — one markdown file per feature, version-controlled as the source of truth. The format is:
```
# Feature Name
role: admin | buyer

- test case — expected outcome
```

The skill runs eight steps in order:
1. **Locate** — reads the given file, or Globs `docs/specs/*.md` for all features
2. **Check existing POMs** — lists any POMs that would be overwritten and asks before proceeding
3. **Clarify** — asks all ambiguous questions in one single message; waits for one reply
4. **Determine pages** — maps test cases to nopCommerce page URLs, deduplicates
5. **MCP exploration** — authenticates once, then `browser_snapshot` per page (accessibility tree, never raw HTML)
6. **Write POMs** — `tests/pages/admin/*.ts` or `tests/pages/public/*.ts`, extending `BasePage`
7. **Write specs** — `tests/specs/*.spec.ts` using generated POMs
8. **Report** — lists new (`✓`) and overwritten (`~`) files, flags uncertain selectors

Spec files import `{ test, expect }` from `tests/fixtures/index.ts` and use the `authenticatedAdmin` fixture — no login code in tests.

POMs are treated as generated output — edit `docs/specs/` instead of editing POMs directly, then re-run `/generate-tests` to regenerate.

## CI

GitHub Actions runs on push/PR to main/master. All credentials are passed via GitHub Secrets (same names as `.env` variables). CI runs chromium only with 1 worker and 2 retries.
